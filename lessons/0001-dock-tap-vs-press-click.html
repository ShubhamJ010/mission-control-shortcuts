Lesson 0001: The Dock Two-Finger Tap vs Press-Click Bug

Welcome to Lesson 1. In this lesson, you will learn why your trackpad's physical two-finger right click stopped working over the macOS Dock, and how to engineer an elegant, zero-overhead fix.

1. The Four Stages of the macOS Event Pipeline

macOS processes trackpad and pointer interactions through four distinct architectural layers:

[ Trackpad / Mouse Hardware ]
       │
       ├─► 1. Raw Capacitive Contacts ─► MultitouchSupport.framework (Private C Driver API)
       │                                     └── Finger structs: position, count, state (touches/lifts)
       │                                     └── Used by MCSC: GestureEngine (TwoFingerDoubleTapRecognizer)
       │
       └─► 2. Hardware Actuation ──────► IOKit HID Driver
                                             └── Dispatches raw IOHIDEvent (contact pressure, button states)
                                             │
                                             ▼
                                         3. WindowServer & Quartz (Core Graphics)
                                             └── CGEventTap (e.g. kCGHIDEventTap / DockInteractionSuppressor)
                                             └── Reads/filters CGEvent, mouseEventPressure, and event types
                                             │
                                             ▼
                                         4. AppKit (Application Runtime)
                                             └── NSApplication.sendEvent(_:) converts CGEvent to NSEvent
                                             └── Delivers down NSWindow and NSView Responder Chain
                                             └── Triggers NSMenu context menus or Dock icon bounces

2. The Nature of the Bug: Blunt Instrument Gate

To support the 2-finger double-tap gesture (which resizes windows to 60% or 90%), MCSC needs to prevent macOS from opening the Dock icon's context menu during the gesture.

The Root Cause Code (ShortcutViewModel.swift:416): 
if dockHovered {
    self.dockSuppressor.isSuppressing = true
} else if !mcActive {
    self.dockSuppressor.isSuppressing = false
}

Notice the flaw: whenever touches.count >= 2 over the Dock, MCSC sets isSuppressing = true. Inside DockInteractionSuppressor.swift, any click event (left, right, other) was unconditionally swallowed when isSuppressing was true:

if suppressor.isSuppressing {
    if suppressor.isDockHoveredProvider?(location) ?? false {
        return nil // SWALLOWED!
    }
}

3. Tap-to-Click vs. Physical Press-Click (Force Touch & Mechanical)

Why did this break physical right-clicks? Consider the hardware mechanisms and event data:

  • Force Touch Trackpads: Four capacitive strain gauges measure downward force, actuating the Taptic Engine. Firm pressure produces a physical click with kCGMouseEventPressure > 0.0 (typically 1.0). When two fingers are down, placing fingers triggers touches.count == 2, but pressing down should trigger the context menu. The old gate swallowed it because isSuppressing was true!
  • Mechanical Trackpads & Mice: On older MacBooks (pre-2015), Magic Trackpad 1, and external physical mice, actuation is triggered by a mechanical physical microswitch. These physical button presses similarly register positive click state and pressure.
  • Capacitive Tap-to-Click: When the user turns on "Tap to click" in macOS System Settings, no physical switch or force threshold is reached. Instead, macOS WindowServer synthesizes mouse-down and mouse-up events upon finger lift. These synthesized events report kCGMouseEventPressure == 0.0.

4. The Architectural Fix

The fix consists of three architectural layers:

  1. Pressure-Aware Pass-Through: In DockInteractionSuppressor, read event.getDoubleValueField(.mouseEventPressure). If pressure > 0, it is a physical press-click or external mouse click: never swallow it.
  2. Gesture-State Coupling: Remove the naive touches.count >= 2 override from ShortcutViewModel. Only suppress zero-pressure synthesized taps when TwoFingerDoubleTapRecognizer is in active double-tap states (tap1Down, tap1Up, or cooldown). When fingers are held > 0.22s, the recognizer enters idle, and suppression disarms.
  3. Settings Safety: If isTwoFingerDoubleTapEnabled is false, never suppress clicks.
